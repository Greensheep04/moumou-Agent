# 老师任务评测

[简体中文](EVAL.md) · [English](EVAL.en.md)

## 统一协议，显式区分题源

[eval/tasks/README.md](../eval/tasks/README.md) 是默认老师题库，保留各组原始角色初始化和两个任务文本：

| 场景 | 固定成员 | 顺序任务 |
| --- | --- | --- |
| `scenario_1` | Technical Lead、Software Developer、Test Engineer、Release Manager | 会议室预订系统，随后使用率仪表板 |
| `scenario_2` | Editor-in-Chief、Reporter、Fact-Checker、Editor | 校园新闻报道，随后 AI 写作检测器事实核查 |
| `scenario_3` | Fund Manager、Research Analyst、Risk Manager、Marketing Specialist | 模拟投资方案，随后半导体 HTML 演示 |

老师十份 Markdown 全部作为原始输入保留。加载器记录题源哈希和原提示词，不编造验收测试或答案。完整老师题库有六个根目标；Task 2 沿用同组四成员、私有角色工作区、经验、真实 Task 1 结果及对话引用。分工、实现和合适的检查由执行过程与人类协商确定。

正式团队适配器传入完整原角色提示词、当前目标和全部验收条件；先限制可选历史、依赖摘要、结论板和经验，并在私有 `.evaluation/context/<digest-prefix>.json` 中保留精确辅助内容。新文件名使用哈希前 32 个十六进制字符，引用和校验保留完整 SHA-256；不同内容的碰撞明确拒绝，不重命名旧归档。必需指令超过开场预算时，`ContextAdmissionError` 在调用 LLM 前拒绝准入。归因模型遗漏前先检查实际发送的输入；框架截断属于系统失败，未完成目标仍保留在计划分母中。

委派开场还固定保留当前仓库中经校验的祖先原目标，按根到直接父任务排列并记录 UTF-8 SHA-256。引用与当前子目标、角色和验收分别呈现，保留原限定及未知项；只沿 `parent_id`，不从 `deps`、上一阶段或角色名称猜祖先。父任务私有人答、审批、记忆及文件不随引用共享，也不产生额外搜索授权。普通和老师 builder 均先为完整引用分配必需预算，重入、答复刷新及压缩保持它们；信息已发送不等于模型正确采用。

低优先级[补充题库](../eval/supplementary/README.md)将原自建十五题保留为相同角色/任务约定的 Markdown，共八组，除最后一组单题外每组两题。必须显式 `--tasks eval/supplementary`，不会自动降级运行；使用独立结果和十五目标分母。原 setup 与检查信息保留，但历史脚本答案元数据不授权真实人工作答或审批。

记忆迁移题的原 warmup 已作为题目中的明确准备前提。团队应实际执行并记录；CLI 不运行旧消融计划，也不会自动注入记忆。迁移结论需要真实准备和检索证据。

在项目根目录激活环境后：

```powershell
# 只查看题源，不需要密钥、不调用模型、不创建运行目录。
python -m moumou --plan

# 相同正式入口，使用真实控制台输入及质量审阅。
python -m moumou
python -m moumou.eval.cli --tasks eval/tasks

# 单组、真实文件输入、新输出目录。
python -m moumou --scenario scenario_1 --human files --out runs/test/NEW_SESSION

# 老师任务之后可显式选择自建题，协议相同。
python -m moumou.eval.cli --tasks eval/supplementary --plan
```

`make test` 和 `make eval` 使用该协议。确定性框架回归使用 `make unit-test` 或 `python -m pytest -q`；这些测试提供实现证据，不是老师任务完成率。

`tests/` 中可包含题源加载器和入口检查，但老师原题位于 `eval/tasks/`，不是这个测试目录。
有意义的回归源码建议随代码保留，老师没有单列 `tests/` 为硬性交付物；缓存、临时文件和本地输出无需上传。

## 人类交互与质量

正式评测使用真实问题、工具权限和交付后的质量审阅。控制台模式直接询问；文件模式将请求保存在 `SCENARIO_ROOT/human/pending/`，并从 `human/responses/REQUEST_ID.json` 接受对应的 `HumanResponse`；字段见[运行说明](SETUP.md)。没有预设答案或自动同意。

质量请求发出前，任务结果已保存供检查。明确人类同意记录为 `human_accepted`；拒绝记录为 `human_rejected`，跳过该组后续依赖任务。普通任务阶段错误、拒绝和未完成交付不阻止其他已配置独立组执行；初始化、配置或清理失败属于整场基础设施停止，取消/KeyboardInterrupt 也停止整场。未尝试组在完整分母中保持未知。

Agent `DONE`、子任务测试全绿和启动器可运行是不同证据。空根验收清单属于自报，不能称机器验证。`--quality-review deferred` 保持质量未知，不因 Agent 已停止就产生 verified success。独立质量评估可使用完整保存对话和输出，但必须记录实际评估者和决定；默认 CLI 等待真实人类审阅，不伪造独立模型分数。

同任务委派恢复会从 scoped 问答账本恢复已答内容，保留原 ID 和来源；原待答问题按原身份续接，不编造答复。这些事实进入固定开场上下文，工具审批授权不会复用。人类端口记录可包含明确授权的操作者协助，仍须与新手工答复或质量批准区分。

后续质量决定使用[运行说明](SETUP.md)中的追加式 `moumou.eval.review`。原质量与有效质量覆盖分别可见；覆盖不会恢复执行或改写原结果。

## 密钥、搜索和上限

使用课程 DeepSeek/HKGAI 配置，密钥保存在本地 `.env`，见[环境说明](SETUP.md)。真实联网搜索需要 `TAVILY_API_KEY`。初始 `--search-requests 6` 覆盖一组两题和全部四角色，缓存命中、去重调用及真实 provider 尝试分别记录。增加配额需要明确人类授权；它不限制学校模型调用额度。

每节点执行上限是协作式循环保护。应记录实际等待、失败调用及中断；场景墙钟时间不等于并发 span 累计时间之和，也不是整进程硬截止保证。

## 结果与中断

默认每次在 `runs/test/<run_id>/` 下新建目录，也可通过 `--out` 指定新路径。`test.json` 保存计划和场景状态，`active.json` 标识当前阶段。每组任务结果、完整 `dialogue.jsonl`、数据库、搜索审计和私有角色输出均保留在该目录；运行产物和密钥不提交。

失败和中断证据必须保留。强制停止可能使 `test.json` 仍记录 `running`，不能改写为正常完成；归档应附实际停止/清理证据和未答请求。CLI 不自动恢复已有输出目录。之后续接或新试验需要明确且有记录的状态转移方案，保留原记录和未知质量。

新交付保存带哈希的不可变文件副本及阶段记忆/失败快照；场景关闭时的状态快照可保留未完成节点作诊断，不算交付任务。旧运行没有快照时保持未知，后续工作区文件或实时 `memory.db` 不能冒充历史状态。

```powershell
python -m moumou.eval.report --run runs/test/EXISTING_SESSION
```

离线重建只使用保存的任务证据，不调用模型、不重新验收、不回答未决问题。旧归档可用于历史分析，但不构成另一个正式题库或入口。未被索引的任务结果或不一致身份属于完整性错误，应明确修复归档后再评分，不能静默纳入或丢弃。

报告的 `suite_wall_time_s` 仅使用保存且带时区的 `started_at` 与 `finished_at`。任一端点缺失则未知；格式无效、无时区或顺序颠倒则拒绝。它包含该区间内等待和未完成阶段；`delivery_time_s` 只覆盖保存交付的样本，`n=0, sum=0` 不代表整场执行零秒。`report_builder.source_sha256` 与原 manifest 的 `code` 启动快照分开，重建不会改变运行来源。

离线 `moumou.eval.analysis` 和 `moumou.eval.replay` 提供保存的失败/记忆观测及供 P2 使用的只读 JSON，保留原事件、行哈希及 scenario+task 身份，分别呈现已答、待答和已写入但未消费的答复。当前候选实际验证状态见[性能与验证报告](PERFORMANCE.md)。命令示例、导出结构或历史回归不能证明当前质量或 P2 已签收。

## 报告清单

- 写明题源哈希、选择场景、模型、环境及实际输出目录。
- 保留全部已选根目标分母，包括未发布、未完成和未审阅目标。
- 分开报告 Agent 完成、机器验收和已审阅质量。
- 区分本题子树/阶段调用与场景累计观测。
- 报告交付时间、审阅等待、usage 缺失覆盖及搜索尝试。
- 链接实际对话、产物和检查，说明失败与剩余不确定性。

[指标口径](metrics.zh-CN.md)定义具体字段。框架回归通过或自建实验完成不代表老师六目标通过；只有实际执行和有记录的质量证据才能支持该结论。[交付清单](DELIVERY.md)将这些记录对应到架构、性能报告、贡献截图和最终演示要求。

## 原文证据与交付质量

正式老师入口在计次搜索之外注册`source_history`与`read_source`。同场景四角色共享公开查询、URL、摘要、原始检索时间和请求ID。搜索摘要仍是预览；标记支持某项事实前，应读取真实HTML/纯文本原文，核对具体段落、日期和单位。原文读取记录原始/最终URL、内容哈希和时间，缓存保留原读取时间；不支持的格式、访问失败和证据缺失保持为明确限制。

原文工具只读取已登记公共来源，保持TLS校验并固定已验证公共IP，拒绝私网、密钥URL、搜索引擎绕额度、访问障碍绕过、超大/压缩响应。系统DNS给出不可用地址时，可使用固定Cloudflare HTTPS DNS，保留解析来源，不改变本机网络设置。已登记arxiv PDF仅允许同ID同版本的HTML/摘要变体并记录派生关系，不解析PDF。

显式复用公开研究可使用：

```powershell
python -m moumou.eval.cli --scenario scenario_2 --reuse-sources runs/test/PRIOR_SESSION --search-requests 0 --quality-review deferred --out runs/test/NEW_SESSION
```

源运行须有终态保存清单及稳定公共缓存；保留原检索时间和请求ID，缓存未保留的原查询文字标为未知。不导入人答、产物、记忆或评分。新manifest的`source_reuse`明确记录复用；既不计为新搜索，也不冒充本次搜索缓存命中。此类实验应与全新研究基准分开报告。

老师适配器还检查最终根交付文档的本地引用。缺失或未显式列入`result.files`的配套文件/资产会在发布前得到可纠正的`result_rejected`反馈；应明确包含预期公开文件或修正引用，不自动补全任何文件。这是打包检查，不能证明事实正确；仍须独立核对重要主张、原文、日期、比率和计算，不能自动产生人工质量批准。

成功抓取原文后，新版本不可变保存 raw/text 及规范化元数据，最新 URL 缓存指针单独更新。抓取身份、原时间、来源请求及明确格式派生关系在计算哈希前归档；缓存服务保留这些身份。读取结果的 `metadata_sha256`、`raw_sha256` 和 `text_sha256` 指向当时证据，不是后来最新网页。旧库只核验回填仍存在的当前行并标明来源，留存开始前丢失的内容保持不可得；操作员补充副本保留独立来源，不为让历史检查通过而迁移原始验收档案。

正式入口还注册只读本地工具 `verify_source_quote`，在团队配置后一次性绑定实际提供方返回的角色工作区。提交真实读取返回的 `metadata_sha256` 和引文，工具只检查那个已留存版本，不发 HTTP、不搜索、不使用最新版本补缺；角色不能传入自贴原文、文件路径或其它命名空间。默认 `exact` 逐码点匹配；`collapse_whitespace` 只折叠 Unicode 空白，不改数字、日期、大小写或标点。结果区分字面匹配 `true`、不匹配 `false` 与证据未知 `null`；坐标属于保存的提取文本或明确标记的归一派生文本。工具 `ok`、字面匹配和事实正确是三件事，仍须阅读上下文、核对出处口径并独立复算。

纠错补充轮保持自己的计划、代码和授权范围，不与默认六目标混算。`DEAD`、未发布阶段及零正式产物仍按原记录报告；从角色私有目录保全的候选文件仅能支持明确标记的局部取证检查，不能冒充正式根交付。按版本的结果见[性能与验证报告](PERFORMANCE.md)；实现回归不补造人工质量、闭集成绩或贡献截图。

例如，基于 `6a830670` 的 `news-reviewed-revision-01` 与 `fund2-reviewed-revision-01` 均在重复 HTTP 504 后以 `DEAD` 结束，没有正式根产物导出；新闻 Task 2 没有运行。对应候选文件的局部取证检查不改变这些正式状态，也不构成老师题通过。

模型计划须为每个子任务显式填写 `deps`；遗漏属于可纠正提案错误，框架不从文字猜边。成功审批备注通过 scoped metadata 进入后续角色观察，与工具 stdout/stderr 分开；它不增加搜索额度、不创建可复用授权，也不是质量复核。文件搜索还报告大文件跳过及输出限制，空匹配不是对未检查文本的穷尽结论。

独立内容审计仍可能否决 Agent DONE 且结构完整的交付。内容问题、模型/协议失败及辅助修订应与实现回归、原人工质量字段分开。跨源码版本比较时保留研究复用和操作员澄清记录，不能合并成同一版本六目标最终成绩。

## 最终文件引文、读取范围与可选流式传输

正式入口还注册 `verify_artifact_quote` 和 `source_access_audit`，在团队配置后绑定实际角色工作区。前者从当前角色自己的 UTF-8 文件读取零基半开 Unicode `[start,end)` 切片，返回整文件、切片及精确来源版本的哈希，不接受模型另贴引文。文件之后有任何改动，旧核对不能自动用于新整文件；字节相同的子任务副本可以建立内容身份对应，但不证明主管阅读或核对过。

后者默认报告当前角色、当前任务的公开来源访问记录，显式参数可查看同组其他角色或历史任务。它通过 `SourceAuditStore` 只读查询现有来源库，不初始化、迁移、搜索或读取私有人答/记忆。成功、失败、缓存、版本和已服务字符区间都按返回事件窗口报告；跟随分页游标，缺失旧版本或分页信息保持 unknown。抓取整页、向角色返回部分字符和模型理解是不同事实，不能把有限窗口的零记录写成“从未读过”。

每次交付在人工质量审阅前保存 `task_1-artifact-quote-evidence.json` 或 `task_2-artifact-quote-evidence.json`，任务结果的 `artifact_quote_evidence` 引用其路径、SHA-256、状态和计数。该文件仅将当前任务树的工具自有记录与不可变交付快照绑定，区分 `matched`、`not_found`、`unknown` 和 `unapplied`；整文件已变、前阶段记录或缺失证据不会补成匹配。记录丢失使证据不完整，损坏快照保持不可用。侧证据中的覆盖率、事实和质量判断保持 null；它不代替人工审阅，deferred 质量仍未知。

依赖角色开场时，团队上下文可加入原生文件核验凭证的有限摘要。可信当前仓库必须记录同范围、状态为 `DONE` 的直接依赖；只有同时列入 `result.files` 和已接收 `artifacts` 的文件才可参与。摘要只读取接收者自己工作区中已整合的文件，并仅将凭证用于当前字节一致的版本。显式列为直接依赖的上一根任务也可参与；这不会暴露生产者的私有文件、人答或完整历史，也不沿传递依赖查找。

开场摘要最多 2000 字符及 8000 UTF-8 字节。完整、简略、空摘要依次纳入正常上下文预算，必需目标、祖先引用和同任务已答信息仍完整保留。凭证缺失、被省略或不完整都表示既往核验未知，不能写成生产者“没有核验”。部分切片匹配不等于所有引文或内容质量通过。绑定与范围见[接口说明](INTERFACES.md)。

通用质量规则还要求分别保留指标测量日期与规则生效日期，避免颠倒条件概率或跨总体外推；区分原始发言人和实际读取的二手页面，逐项区分有限支持、缺证据与反证。这些是审阅指令，不是自动语义评分器；对新老师运行的实际改善仍待验证。

`--llm-transport buffered|stream` 默认 `buffered`，保留原客户端。需要显式试用 SSE 时，仍使用同一入口和新输出目录：

```powershell
python -m moumou --llm-transport stream --out runs/test/NEW_STREAM_SESSION
```

可选学校推理设置必须与 stream 模式一起显式选择：

```powershell
python -m moumou --llm-transport stream --llm-reasoning-effort none --out runs/test/NEW_REASONING_SESSION
```
