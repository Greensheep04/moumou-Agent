# P1：执行与工具层

[简体中文](P1-执行与工具层.md) · [English](P1-execution-and-tools.en.md)

P1 通过共享 Tool 与 WorkspaceProvider 契约提供文件操作、代码执行、联网检索和 Git 能力。老师要求的能力必须满足；后端布局、搜索提供方和工作区实现可在接口对齐后调整。

本文说明当前代码与交接要求。源码存在不等于当前回归已通过、同伴已签收或老师任务质量已验收。

## 责任与实现

| 范围 | 当前文件 | 责任 |
| --- | --- | --- |
| 文件工具 | `src/moumou/tools/filesystem.py` | 相对路径 UTF-8 文件操作与产物声明 |
| 代码执行 | `src/moumou/tools/execution.py`、`src/moumou/sandbox/process.py` | 命令/Python、输出上限、超时及取消清理 |
| 路径检查 | `src/moumou/sandbox/local.py` | 解析路径，拒绝越界及受保护元数据 |
| Windows 进程 | `src/moumou/sandbox/winjob.py` | 原生 Windows 进程生命周期支持 |
| Git | `src/moumou/tools/git.py` | 结构化本地 Git 与独立类别的远端推送 |
| 搜索 | `src/moumou/tools/search.py` | 已配置 Tavily 的结构化检索 |
| 工作区 | `src/moumou/adapters/workspace.py`、`src/moumou/workspace/git.py` | 本地目录及可注入的 GitWorkspaces 后端 |

默认 Engine 使用 LocalDirs。正式团队适配器在提供方外包装稳定的角色私有目录，以延续连续任务。GitWorkspaces 是可用的注入后端，不代表每次正式运行都使用 Git worktree。

与 P3 对接时，可选 `register_private_evidence` 钩子仅在 Git 本地元数据中登记实际上下文及对话文件，
不暂存或提交私有文件。普通脏工作树拒绝、证据可读性和产物隔离保留；未登记文件仍由原检查识别。
含有私有证据的工作树会保留，release 不会默默删除这些被 Git 排除的文件。

## 当前注册能力

`default_tools()` 中实际名称如下：

| 能力 | 工具名称 | 审批类别 |
| --- | --- | --- |
| 读文件、列目录、搜索 | `read_file`、`list_files`、`search_files` | `fs_read` |
| 创建/覆盖/追加、文本替换 | `write_file`、`apply_patch` | `fs_write` |
| 删除文件或显式递归目录 | `delete_file` | `fs_delete` |
| 执行命令和 Python | `shell`、`run_python` | `shell` |
| 本地 status/diff/add/commit/log/branch/merge | `git` | `git_commit` |
| 推送指定分支至已配置远端 | `git_push` | `git_push` |
| 返回标题/URL/摘要的网络搜索 | `web_search` | `network` |

注册表还包含 `echo` 及编排控制名称 `ask_human`、`submit_result`、`submit_revision`、`submit_plan`。控制调用由编排层处理，不是独立 shell 工具。文档输出使用 Markdown/纯文本，专有文档格式解析不属于必需交付。

Gate 统一负责审批策略与 trace。正式会话要求 Git 暂存/提交以及其他已配置关键操作经过审批；角色不能通过选用工具给自己授权。P1 执行获得授权的操作并返回结果，不回答业务问题或批准质量。

## 共享契约

工具实现 `Tool.run(args, ctx) -> ToolResult`；工作区后端实现 WorkspaceProvider 的 `allocate`、`release`、`integrate`。精确 schema 见[共享接口](../INTERFACES.md)，不在本说明重复完整模型。

- 校验参数，失败返回结构化结果和可读错误。
- 文件路径解析后保持在 `ctx.workspace` 内，包括遍历和符号链接目标。
- 限制 stdout/stderr，正确标记 `truncated`，保留退出码和错误。
- 返回相对产物路径，包括相关删除。
- 超时或取消时，在返回前清理支持范围内的子进程。
- 用 IntegrateResult 报告实际复制路径、冲突与错误，不能隐藏冲突。

跨工作区只传递显式产物，不共享整个目录或间接依赖文件。Worker 校验 `submit_result.files`，验收后复检并发布整批有效声明；P1 整合应区分“工作通过验收”与“交付整合冲突”。

## 原生 Windows 与搜索

运行前激活 Python 环境；本项目本地演示环境为 Conda `nlp`。`run_python` 使用项目解释器，框架的 Python 命令兼容不会把 POSIX shell 语法转换成 Windows 语法。可复现命令和配置见[安装说明](../SETUP.md)。

当前 `web_search` 需要 `TAVILY_API_KEY`。正式评测由 P3 搜索记录包装：每场景初始六次新检索由四个角色和连续任务共享，缓存/去重另计，额外额度须显式批准。学校 DeepSeek/HKGAI 模型访问单独计量。其他搜索提供方是需要保持契约及准确计量的设计选项，不是当前已经交付的能力。

## 隔离和交接边界

LocalJail 是应用级路径检查，不是任意 shell/Python 代码的操作系统安全沙箱。进程超时清理不等于内核级隔离，正式交互会话在人类等待期间也没有统一强制截止时间。

正式团队使用 project:role 逻辑记忆身份与连续私有目录；通用 role@task 实例仍共享 project-role 策略。工具和工作区变更须保留身份与显式产物传递。

P0 消费工具、审批与整合结果，P2 展示实际决定/输出，P3 保存产物、时间、错误和搜索证据。字段对齐需实际消费者检查，不能替同伴签收。
