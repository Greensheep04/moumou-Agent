# P1 —— 执行与工具层

[简体中文](P1-执行与工具层.md) · [English](P1-execution-and-tools.en.md)

> 这是全组耦合最低的一块。你只需要对 **1 个接口（`Tool`）** 负责，不需要知道 Agent 是怎么做决策的。

| 项 | 内容 |

| 覆盖的课程功能 | 5 独立执行环境 · 6 联网搜索 · 7 文件与代码执行 · 8 Git/GitHub |
| 预估工作量 | 约 26%（≈18 人日，全组第二重） |
| 上游依赖 | P0 的 `contracts/`（第 1 周末交付） |

## 一、你负责的模块

| 目录 | 技术名称 | 干什么 |
| --- | --- | --- |
| `sandbox/` | 执行沙箱（Execution Sandbox / Workspace Isolation） | 每个 Agent 一个独立目录，只准在自己目录里动；执行有超时、有输出截断 |
| `workspace/` | 工作区管理（Git Worktree 管理） | 同一个代码库拆成多个分身，多 Agent 各改各的分支，最后合并 |
| `tools/` | 工具层（Tool Implementation / Function Calling） | 8 个工具，暴露给 LLM 调用 |

## 二、需要实现的接口（本层已冻结）

```python
# contracts/tool.py —— 由 P0 提供，你写它的实现类
from pathlib import Path
from typing import Protocol, Literal
from pydantic import BaseModel

ActionClass = Literal[
    "fs_write", "fs_delete", "shell", "git_push", "network", "install"
]


class ToolContext(BaseModel):
    agent_id: str
    task_id: str
    workspace: Path                 # 该 Agent 的专属工作区，你只能在这里面读写
    env: dict[str, str] = {}


class ToolResult(BaseModel):
    ok: bool
    stdout: str = ""
    stderr: str = ""
    exit_code: int | None = None
    error: str | None = None        # ok=False 时必填，一句话，直接给 LLM 看
    artifacts: list[str] = []       # 产物相对 workspace 的路径


class Tool(Protocol):
    name: str                       # 唯一名字，如 "shell_exec"
    params_schema: dict             # JSON Schema，直接喂给 LLM 做 function calling
    action_class: ActionClass | None  # None = 免审批；非 None = 触发人工审批
    async def run(self, args: dict, ctx: ToolContext) -> ToolResult: ...
```

### 要交付的 8 个工具

名字和参数你自己定，但功能必须齐：

| 工具 | 必须支持 | action_class |
| --- | --- | --- |
| `fs_read` | 读文件、列目录、grep 内容 | `None` |
| `fs_write` | 创建 / 覆盖 / 追加 | `fs_write` |
| `fs_delete` | 删文件 / 删目录 | `fs_delete` |
| `shell_exec` | 跑任意 shell 命令 | `shell` |
| `python_exec` | 跑 Python 脚本或片段 | `shell` |
| `fs_apply_patch` | 按 old→new 文本替换（可选，但强烈建议：比整文件重写省 token） | `fs_write` |
| `git` | status / diff / add / commit / log / branch / merge | `commit` 免审批 |
| `git_push` | 推送到 GitHub | `git_push` ← **必须审批** |
| `web_search` | 联网检索，返回结构化结果（title / url / snippet） | `network` |

## 三、实现约定（只约束外部表现）

1. **异常转成结果**。失败建议包装成 `ok=False` + 可读的 `error` 返回。
   原因：这条 error 会原样回给 LLM，让它自己改。抛异常会直接打断编排循环。
2. **子进程需要清理**。框架外层有 `asyncio.wait_for` 兜底超时；协程被 cancel 时建议一并 kill 子进程，否则跑几十个任务后机器会变慢。
3. **路径需落在工作区内**。`..`、绝对路径、符号链接都建议 resolve 之后校验，越界时返回 `ok=False, error="path_outside_workspace"`。
4. **输出建议截断**。stdout/stderr 超过 8KB 截断并标 `[truncated]`。否则一次 `cat` 大文件就把 LLM 上下文撑爆。
5. **产物需回填路径**。新建 / 修改的文件放进 `artifacts`，编排层要用它做合并和展示。
6. **审批与日志由框架统一处理**。框架会在调用**之前**做审批、在调用**前后**包 trace span，工具内不必重复 print 日志或弹确认框。

## 四、验收标准

已提供：`tests/test_tool_contract.py`，跑过它就等于完成。大致长这样：

- 每个工具的 `name` / `params_schema` / `action_class` 齐全，且 `params_schema` 能通过 `jsonschema.validate`
- 正常输入返回 `ok=True`
- 给一个必炸的输入（不存在的文件、错误的命令），返回 `ok=False` 而**不是**抛异常
- 给一个 `../../etc/passwd`，必须被拒
- 给一个 `while True: pass`，必须在超时内返回，且进程确实被杀了（用 `ps` 验证）
- 给一个 100MB 输出，必须被截断

## 五、实现方式自行决定

- `LocalJail` 还是 `Docker`：**建议 LocalJail 必做、Docker 加分**
- worktree 还是直接 `cp -r` 复制目录
- 搜索用哪家 API（Tavily / Serper / DuckDuckGo）
- 文件大小上限、默认超时秒数
- 代码怎么组织、要不要基类
- 错误信息的措辞

## 六、本模块范围之外

- 不管消息怎么传（那是 P2）

## 七、答辩时要能讲清的两点

1. **我们的隔离是"应用层路径越界检查"，不是内核级隔离。**
   Docker 后端可以提供真隔离，但演示时为了性能默认关掉。
   **这个限制要如实写进架构文档**——写清楚"我们知道它的边界在哪"，比假装做到了更得分。
2. **`git worktree` 让多个 Agent 在同一个仓库上并行改不同分支，最后 `git merge` 合并。**
   这是"独立环境 + 最终整合"这个要求最直接的实现，演示时要展示 `git log --graph`。
