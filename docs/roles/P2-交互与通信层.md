# P2：交互与通信层

[简体中文](P2-交互与通信层.md) · [English](P2-interaction-and-channel.en.md)

P2 负责私聊/群聊、人类交互和已记录执行过程的展示。老师要求 Agent 与人的私聊、多 Agent 与人的群聊，以及主动澄清和权限询问。最小 CLI、bot 或文本界面即可；精美前端没有额外加分。

这些责任固定，传输、持久化和回放展现可在共享契约下自行选择。

## 当前边界

| 范围 | 契约或实现 | 状态边界 |
| --- | --- | --- |
| Agent/人类寻址 | `contracts/message.py`：Message、Scope、Channel | 共享 API |
| 澄清、审批和复核 | `contracts/human.py`：HumanIO | 共享 API，决定策略属于编排层 |
| 问题恢复 | 可选 ResumableHumanIO | 仅原范围内的问题，不复用工具授权 |
| 默认 Channel | `adapters/bus.py`：InMemoryBus | 内存参考，不是持久生产交付 |
| 正式控制台/文件交互 | `eval/human.py`：ConsoleHuman、FileHuman | 当前正式端口，保存真实请求/答复证据 |
| 回放数据 | `eval/replay.py` | P3 只读导出，P2 实际消费验收仍待完成 |

实现布局可自行选择，文档应对应真实源码路径。不能从内存参考实现或一个导出文件推断持久传输、回放界面已经完成。

## Channel 契约

按[共享接口](../INTERFACES.md)实现 `publish(msg)`、`subscribe(agent_id, callback)`、`history(scope, limit=50)`。人类使用固定 ID `human`；Message 包含 project/conversation/task 身份、发送者、接收者、消息类型、正文及元数据。

- 私聊只到达对应成员，不能泄漏给无关订阅者。
- 群聊/广播保持在预期项目和会话内。
- 持久实现先保存再投递，历史按时间升序。
- 订阅回调不能阻塞消息总线，取消和错误须可见。
- 过滤须包含 project/conversation 及成员，不能只在显示页签上隔离。

内存默认实现可供框架验证行为，但不证明重启持久化、完整私聊隔离或生产消费者已签收。

## HumanIO 与恢复

`ask(req) -> HumanResponse` 展示原请求并返回显式答案，`notify(msg)` 展示通知。以下含义分别处理：

| 请求 | 必要交互 |
| --- | --- |
| `question` | 匹配原 request ID/选项的非空澄清 |
| `approval` | 针对所展示操作和完整参数明确 approve/reject |
| `review` | 根据证据明确给出质量/提议判断及可选反馈 |
| `steer`（Channel） | 运行中调整方向，不是操作授权 |

界面展示和记录决定，不自行决定业务要求、修改 Gate 策略、自动接受产物或制造答复。Scripted/自动批准的开发适配器不能提供正式人工授权。

同任务持久恢复应保存 project/conversation/task/role 范围、原 request ID/正文及来源。可选 `resume(req)` 继续原待答问题或取回已消费答复，不新造 ID、不复用审批，也不把业务澄清升级为质量接受。已消费答复恢复时不重复回调；未消费回调如有外部副作用，须按 request ID 幂等。

取消应停止活跃等待和后台任务，并如实保留 pending/consumed 证据。待答文件不代表进程仍活着，暂存答复不代表 Agent 已消费；记录匹配也不能认证文字是手工输入还是辅助转交。

## 正式流程及 P3 交接

正式入口为 `python -m moumou`，也可用 `python -m moumou.eval.cli`，通过真实控制台/文件交互。老师题默认，补充题须显式选择。队列/答复格式见[安装说明](../SETUP.md)及[评测流程](../EVAL.md)。

正式团队成员在连续任务中保留稳定 role ID 和私有目录，长期记忆按 project:role；通用实例仍保留原共享策略。界面应保留记录中的实际身份和范围。

读取 P3 回放时使用场景+任务组合身份、原 span ID/父关系及来源/行哈希。保留原状态，区分原始与复核后的有效质量，缺失关系或测量显示未知。不能凭缺失数据补造父边、零耗时、质量通过或运行存活。

界面可选时间线、表格或树，但须分别展示人类澄清/审批、Agent 完成、机器验收和质量判断。P3 可以导出不等于 P2 真实界面已经加载并接受该 schema。

## 验收与交付

保留有意义的 Channel/HumanIO 回归。实际检查应覆盖私聊隐私、群聊投递、项目/会话过滤、重启历史、原 ID 问题恢复、显式拒绝、取消及消费者 schema。运行后记录环境、命令、结果和边界。

当前变更接口和恢复代码仍待回归与真实消费签收。最小界面、框架夹具通过或已有导出都不能单独证明老师目标质量。P2 不负责提示词、工具执行、审批策略或性能计分。

交接以[交付要求](../DELIVERY.md)、[共享接口](../INTERFACES.md)及[P3 证据责任](P3-数据与评测层.md)为准。
