| --- | --- | --- |

## 二、需要实现的接口（本层已冻结）

```python
# contracts/message.py —— 由 P0 提供，你写实现
from typing import Protocol, Callable, Awaitable, Literal
from pydantic import BaseModel


class Scope(BaseModel):
    kind: Literal["dm", "group"]
    project_id: str
    conversation_id: str
    members: list[str]          # dm: [agent_a, agent_b]；group: 所有成员


class Channel(Protocol):
    async def publish(self, msg: Message) -> None: ...
    def subscribe(
        self, agent_id: str, cb: Callable[[Message], Awaitable[None]]
    ) -> None: ...
    def history(self, scope: Scope, limit: int = 50) -> list[Message]: ...


# contracts/human.py
class HumanIO(Protocol):
    async def ask(self, req: HumanRequest) -> HumanResponse: ...
    async def notify(self, msg: Message) -> None: ...
```

### 核心设计（想清楚这一条，其余都很简单）

**人类 = 一个 `agent_id == "human"` 的普通成员。**

这样私聊、群聊、审批三种交互就变成**同一种机制**，不用写三套：
- 私聊 = `Scope(kind="dm", members=[agent, "human"])`
- 群聊 = `Scope(kind="group", members=[...所有 agent..., "human"])`
- 审批 = 一条 `kind="ask_human"` 的消息 + `HumanIO.ask()` 等回答

## 三、实现约定（只约束外部表现）

1. **`publish` 必须先落盘再投递**。进程崩了消息不能丢，要能回放。
2. **订阅回调不能阻塞总线**。每个回调放独立 task；慢订阅者超时丢弃并记 warning，不能把整条总线拖住。
3. **`history` 按时间升序返回**。
4. **`ask` 必须能被取消**。任务被 abort 时，挂起的审批要能撤回，不能永远等。
5. **UI 退出不能留后台 task**，否则终端卡住退不出去。
6. **UI 层不承担业务判断**。审批策略在编排层，界面侧负责把问题显示出来、把答案传回去。

## 四、验收标准

已提供：`tests/test_channel_contract.py`。把文件里的 `make_bus` 指向你的实现，绿了就算过：

- 两个假 Agent 互发 DM，第三个 Agent **收不到**
- 群聊消息所有成员都收到
- 进程重启后 `history()` 还能读回历史（如果你用内存队列就会挂——所以建议 SQLite 或 JSONL）
- `HumanIO.ask()` 挂起后可以被 `cancel()`
- CLI 能显示一条 `ask_human` 消息并输入 yes/no

## 六、本模块范围之外

- **不组装 prompt**（上下文是 P0 的事）
- 不做决策、不调工具、不连 LLM
- 不写指标、不做评测
- 不定义审批策略（哪些操作要审批由 P0 的策略表决定）

## 七、加分项（性价比极高，建议做）

`ui/replay.py`：从 `TraceStore` 读一次任务的完整 trace，逐条重放——谁派了活、谁调了什么工具、哪一步卡住等人、最后花了多久。

答辩时直接跑这个，比讲架构图强十倍，而且**几乎不占额外开发量**（数据 P3 已经存好了，你只是渲染）。
