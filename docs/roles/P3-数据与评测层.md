# P3：数据与评测层

[简体中文](P3-数据与评测层.md) · [English](P3-data-and-evaluation.en.md)

P3 负责让执行过程与目标质量有据可查。老师要求的任务完成率、执行时间、真实人类决定和原始输入，要与框架实现测试分别记录。

## 负责的接口和文件

| 范围 | 当前责任 |
| --- | --- |
| `src/moumou/store/trace.py` 与 Recorder 接入 | 持久 trace、精确任务查询与 JSONL 恢复 |
| `eval/tasks/` | 老师原始 Markdown：三个四人团队、六个连续目标；默认且第一优先 |
| `eval/supplementary/` | 保留十五个自建题，同一 Markdown 协议；低优先、显式选择 |
| `src/moumou/eval/cases.py` | 原题、角色与任务加载及来源哈希 |
| `src/moumou/eval/team.py` | 固定团队、连续私有工作区及真实交接/历史 |
| `src/moumou/eval/human.py` | 脱敏模型对话与真实控制台/文件 HumanIO |
| `src/moumou/eval/cli.py` | 统一正式入口及任务/场景计量 |
| `src/moumou/eval/search_budget.py` | 场景共享搜索配额及审计 |
| `src/moumou/eval/report.py` | 从当前和历史保存证据离线重建报告 |
| `src/moumou/eval/analysis.py`、`replay.py` | 老师会话失败/记忆观察及带来源的 P2 只读导出 |
| `src/moumou/eval/review.py`、`session_evidence.py` | 只追加的显式复核、不可变阶段及诊断证据 |

存储端口仍是 `TraceStore.append/query` 和 `contracts/store.py` 中的 `MemoryStore` 写入、搜索、枚举、评分及删除方法。必须保留精确事件和记忆范围。按 project-role 过滤，不代表每一种 Engine 运行实例都独立隔离。

正式团队使用稳定角色 Agent ID 和私有角色目录，project:role 对应连续逻辑身份；场景及运行数据库隔离团队。通用 Engine 的逐任务实例仍保留原有共享策略。

## 统一正式协议

```powershell
python -m moumou --plan
python -m moumou.eval.cli --tasks eval/tasks
python -m moumou.eval.cli --tasks eval/supplementary --plan
python -m moumou.eval.report --run runs/test/EXISTING_SESSION
```

`make test` 与 `make eval` 调用同一正式协议；`make unit-test` 运行框架 pytest。老师题优先，自建题保留但不会自动选择或混入老师成绩。原始任务不会被改写成预设流程或人类答复脚本。

Task 2 延续同一团队的四个身份、各自目录、记忆、实际产物及可读对话归档。正式执行使用真实澄清、审批以及默认交付后质量复核。`ScriptedHuman` 只用于确定性框架测试，不能代替正式人工授权。

## 指标与回放契约

- 以实际选定根目标计划为分母：全部老师题为六个，全部补充题为十五个；保留未发布和质量未决目标。
- 分别报告 Agent `DONE`、机器验收和真实人工质量。根目标验收为空时属于自述，不是机器核验。
- 每题自身的子树/阶段调用与场景累计数据分别计量。
- 保存交付耗时、人工复核等待、到复核结束的总耗时及可测用量；重叠 span 不能直接相加当作墙钟，未知不写成零。
- 为 P2 与复核者保留 `runs/test/<id>/test.json`、任务结果、对话、trace、工作区和搜索证据；凭据始终排除。
- 不凭一组成功或一条经验宣称记忆收益、统计显著性。

共享定义见[指标说明](../metrics.zh-CN.md)和[接口说明](../INTERFACES.md)。离线生成报告不会恢复旧会话或回答未决复核；强制停止后即使原始 manifest 仍写 running，也保留原状态及独立停止证据。

分析、回放、复核、问题恢复和阶段快照已实现，并有尚未执行的回归源码。已发布 e35e820 的 905 passed / 8 skipped 只代表历史基线，不验证当前修改版本，也不代表老师六目标质量或 P0/P1/P2 实际签收。

## P3 交付材料

| 交付项 | 必须包含 |
| --- | --- |
| 代码和题源 | 可复现配置模板、老师原题哈希、保留的补充题库及有意义的框架回归 |
| 架构和接口 | 路由/委派、问题恢复、身份/记忆策略、沙箱边界及证据消费字段 |
| 性能报告 | 实际计划、已核验目标、执行时间、观察到的失败、记忆变化、限制及原始证据 |
| 复现说明 | 原生 Windows / 已激活 Conda、命令、模型身份和非秘密配置 |
| 贡献证据 | 仓库链接、真实 Git 历史及截图，展示成员持续的个人开发贡献 |

[交付要求](../DELIVERY.md)定义打包和验收清单，[性能证据](../PERFORMANCE.md)区分已测结果和待测事项。Final Set 发布并真实运行后才能补入最终成绩，任何占位值都不是提交成绩。

## 设计自由度与边界

存储布局、检索实现和报告形式可按情况调整。老师角色提示词、原始任务、真实人类答复及证据完整性必须保留。补充题的 setup/check 信息保留，旧 scripted-answer 元数据不构成真实答复授权。

P0 负责调度、记忆策略和编排语义，P1 负责执行/工具，P2 负责交互/回放。P3 适配这些契约并说明跨模块影响。验证命令显式运行，交付不依赖仓库内 GitHub Actions 工作流。底层历史实验 API 用于历史分析，不构成另一套正式题库入口。
