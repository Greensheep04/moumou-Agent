# 系统架构

[简体中文](ARCHITECTURE.md) · [English](ARCHITECTURE.en.md)

Moumou 将人的要求转换为可持久化的任务图。Agent 可以主动澄清要求、委派子任务、在私有工作目录中执行工具，并通过显式声明的文件交付成果。Agent 完成状态、机器验收与人工复核的目标质量分别记录。

本文描述当前实现。最近补充的问答恢复、trace 和评测功能仍待回归及真实任务验证；代码已经实现不等于已经验收。

## 运行组件

```mermaid
flowchart LR
    H[人类控制台或文件接口] --> C[正式任务会话]
    C --> E[Engine 与调度器]
    E --> R[任务执行器]
    R --> L[课程 DeepSeek 或 HKGAI 模型]
    R --> G[审批 Gate]
    G --> T[工具与私有工作区]
    R --> A[机器验收]
    E --> M[按角色隔离的长期记忆]
    E --> D[任务状态与人类问答记录]
    E --> J[JSONL trace 与 SQLite 投影]
    C --> S[交付与阶段证据]
    S --> O[离线报告、复核、分析及回放]
```

| 组件 | 文件 | 责任 |
| --- | --- | --- |
| 契约 | `src/moumou/contracts/` | 任务、角色、消息、工具、人类及存储接口 |
| 编排 | `src/moumou/orchestrator/` | 状态转换、调度、委派、审批与验收 |
| 上下文和记忆 | `src/moumou/context/`、`src/moumou/memory/` | 内容准入、压缩、检索、反思和评分 |
| 工具和工作区 | `src/moumou/tools/`、`src/moumou/sandbox/`、`src/moumou/workspace/` | 文件、子进程、Git、搜索与产物整合 |
| 交互适配 | `src/moumou/adapters/`、`src/moumou/eval/human.py` | Channel/HumanIO 适配和完整对话记录 |
| Trace 存储 | `src/moumou/trace/recorder.py`、`src/moumou/store/trace.py` | 日志、精确任务查询及 SQLite 恢复 |
| 正式评测 | `src/moumou/eval/` | 原始题源、连续团队、指标与离线证据工具 |

`Engine` 支持注入工具、工作区、Channel、HumanIO 和记忆实现，默认任务状态保存在 SQLite。扩展约定见[接口说明](INTERFACES.md)。

## 一个任务如何执行

1. Engine 持久化根任务，将其从 `PENDING` 变为 `READY`。
2. 调度器根据依赖与并发槽位选出任务，将其变为 `RUNNING`。
3. 执行器分配工作区、接收显式依赖产物、恢复已有澄清，并组装上下文。
4. 模型可以调用工具、询问人类、提交结果或提出任务拆分计划。
5. 框架校验计划后创建子任务。父任务变为 `PENDING`，依赖改为子任务 ID，子任务完成后父任务再次运行。
6. 框架校验声明的文件，执行机器验收，再通过工作区整合接口发布已通过验收的显式产物。
7. 任务终止后写入结论板，并执行符合条件的长期记忆维护。
8. 正式会话保存交付证据并获得人工质量判断；延期复核时保留未知质量。

```mermaid
stateDiagram-v2
    [*] --> PENDING
    PENDING --> READY: 依赖满足
    READY --> RUNNING: 被调度
    RUNNING --> WAITING_HUMAN: 澄清或审批
    WAITING_HUMAN --> RUNNING: 有效答复
    RUNNING --> PENDING: 委派给子任务
    RUNNING --> DONE: 验收通过
    RUNNING --> FAILED: 本次尝试失败
    FAILED --> READY: 允许重试
    FAILED --> DEAD: 重试耗尽
    PENDING --> DEAD: 依赖无法完成
    WAITING_HUMAN --> FAILED: 等待时中断
    RUNNING --> DEAD: 取消或终止
```

图中列出常见路径，完整合法转换以 `contracts/task.py` 的 `LEGAL_TRANSITIONS` 为准。状态变化和对应审计事件在同一事务中写入。重启恢复依据持久状态与剩余重试次数执行，不会把中断改写成成功。

## 委派和身份范围

计划包含角色、子目标、验收和依赖。框架检查角色/工具权限、依赖存在性、无环性及数量/深度限制。通用 Engine 可以在配置上限内生成新角色。

正式题源适配器固定使用每个场景原有的四名成员，拒绝新增身份，同一成员的并发任务串行执行。每名成员在该场景的连续任务中使用稳定 Agent ID 和独立角色目录。

| 数据 | 范围 |
| --- | --- |
| 角色定义、长期经验 | project + role |
| 结论板 | project + conversation + role |
| 人类澄清记录 | project + conversation + task + role |
| Trace 查询 | 当前运行内的精确 task ID |
| 正式团队工作区 | 场景 project + conversation + 稳定 role ID |

通用 Engine 使用 `role@task` 运行实例 ID，但保留 project-role 记忆共享策略。它与正式团队的稳定逻辑身份不同，不能宣称所有运行实例的记忆都独立。正式场景和不同运行通过各自的目录、数据库隔离。

## 上下文与人类决定

通用和正式团队上下文都保留完整当前角色、目标、验收及同任务已答信息。依赖报告、经验、结论板与历史等可选内容先让出预算。必需内容无法容纳时，`ContextAdmissionError` 在模型调用前明确拒绝准入。

正式适配器将完整辅助上下文保存在私有 `.evaluation/context/<digest-prefix>.json` 中。新文件名取 32 位十六进制前缀，引用保留完整 SHA-256，并检查同名不同内容冲突。这些是框架证据，不属于交付项目文件。

问题在等待前持久化。委派、重试或进程恢复后，执行器把原已答信息恢复到固定开头。支持恢复的 HumanIO 可以继续原范围内的待答问题，或取回已消费答复，保留原请求 ID；缺失或冲突记录会明确失败。工具审批仍按每次操作重新进行，拒绝理由随当次工具结果返回模型。

准入与记忆机制见[上下文和记忆](CONTEXT-MEMORY.md)。

## 执行、产物与隔离

工具经过 Gate，根据操作类别执行审批策略并记录结构化结果和 span。正式评测也要求 Git 暂存、提交经过审批。Tavily 搜索由场景内成员和连续任务共享配额，学校模型访问额度单独计量。

产物必须显式声明工作区相对路径。依赖不会共享整个目录，也不会自动传递间接依赖文件；缺失输入需要通过整合接口明确交付或向人类澄清。

本地路径检查属于应用级隔离，不是操作系统安全沙箱：任意执行代码仍可能访问更广的宿主资源。原生 Windows 进程管理及内部评测监督器有各自的清理边界。正式交互会话使用协作式节点限制与工具/模型超时，不提供等待人类期间的统一强制进程截止时间。

## 证据与评测

默认题源是老师原始 Markdown：三个团队、六个根目标。保留的十五个补充目标使用相同协议，须明确选择，不能与老师成绩混算。

每场新运行记录题源/代码/配置身份、对话、人类问答、任务结果、trace 和搜索用量。新交付另保存所选文件的不可变副本、有效记忆元数据与失败事件。场景收尾快照可以保留未完成节点，属于诊断，不增加交付数或目标数。旧运行缺少快照时保持未知。

Recorder 先刷新 JSONL，再更新 SQLite 投影。投影失败会显式记录并退回原日志查询；有效日志可在重开时补导入缺失事件。两份文件不共享事务。自动 span 父子关系表示调用层级，与任务依赖关系分开。

以下离线工具校验保存的证据，不重跑 Agent 或验收：

- `eval.report`：计划分母、耗时、原始/有效质量及已存证据。
- `eval.review`：真实显式人工判断、只追加的复核和替代历史。
- `eval.analysis`：失败及记忆观察，不推定因果收益。
- `eval.replay`：面向 P2 的原始记录与来源索引。

任务阶段普通失败或质量拒绝会跳过本组后续依赖，但继续其他独立组。初始化/配置、资源清理失败或全局取消会停止整场。尚未发布和尚未复核的目标仍保留在原计划中。

没有机器验收条件的 `DONE` 属于自述完成。质量须有自己的复核证据；回归结果、记忆记录或导出文件不能证明老师全部目标通过，也不能代替同伴接口签收。
