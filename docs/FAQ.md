# 常见问题

[简体中文](FAQ.md) · [English](FAQ.en.md)

## 环境

**出现 `ModuleNotFoundError: No module named 'moumou'`**

在仓库根目录使用已激活的项目环境。原生 Windows 目标环境为 Conda `nlp`：

```powershell
conda activate nlp
python -m pip install -e ".[dev]"
```

运行框架测试时使用 `python -m pytest`，确保 pytest 属于这个解释器。[环境配置](SETUP.md)中的直接 Python 命令不依赖 Make 或 uv。

**子进程使用了错误的 Python**

启动项目前先激活环境。仅指定某个解释器的绝对路径，不会自动更新 shell 子进程继承的 PATH。本地也可以用 `conda run --no-capture-output -n nlp python ...` 代替激活。框架对 `python3` 的兼容处理选择当前 Python 解释器，不会把 POSIX shell 语法翻译成 Windows 语法。

## 凭据与搜索

**模型密钥缺失，或者模型名称被拒绝**

在仓库根目录从 `.env.example` 创建 `.env`。`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL` 和 `DEEPSEEK_MODEL` 使用课程提供的准确密钥、兼容端点和模型名称，不能用其他供应商的模型名代替。401 可能表示密钥无效；检查供应商返回和配置时，不要将凭据打印到日志或写入提交。

**模型会自动联网搜索吗？**

当前项目通过注册的 Tavily `web_search` 工具进行真实检索，由 `TAVILY_API_KEY` 配置。模型给出了回答，不代表发生过网页检索。正式 runner 当前没有配置其他搜索供应商。

**为什么模型还能推理，搜索却停了？**

初始额度为每场景六次 Tavily 新请求，四个智能体和两个任务共享；缓存命中与并发去重单独记录。模型 token 使用另一套额度。实际人类可以通过 `/grant-search N` 明确追加搜索额度；恢复后不会将同一个获批请求 ID 重复计入追加。

**不小心提交了凭据**

先向密钥签发服务撤销并更换凭据，再协调仓库清理。后续提交删除该文件，不会抹去它在历史中的内容。真实凭据只保存在被忽略的本地配置中。

## 任务、问答与质量

**默认使用哪个题源？**

`python -m moumou` 和 `python -m moumou.eval.cli` 默认使用 `eval/tasks`，即老师 mid-test 的三个团队、六个目标，也是唯一随附题库。可用 `--tasks` 显式选择兼容的外部 Markdown 目录，其结果按实际任务计划独立计分。`--plan` 检查题源，不调用模型。

**任务已经 `DONE`，为什么质量还是未知？**

`DONE` 是执行状态。没有机器验收条件时只建立自述结果，不能证明正确性。质量在获得真实记录的复核之前保持未知；延期复核不自动将目标判为通过。见[评测流程](EVAL.md)和[指标定义](metrics.zh-CN.md)。

**委派之后应该再问一次已经回答的问题吗？**

当前实现按 project/conversation/task/role 范围保存原问题和答复，并将已答事实恢复到固定上下文前缀。未回答的问题保留原 ID。历史冲突、缺失或损坏会明确报错，不编造回答，也不恢复可复用的工具授权。这些新恢复路径仍待运行回归验证。

**把旧输出目录传进去就能续跑吗？**

不能。正式 CLI 要求使用新的输出目录。引擎内部按范围恢复待答问题，与重启整场正式评测是不同机制。保留原运行和停止证据，再记录状态转移或新运行方案。

**之后如何补做质量复核？**

离线复核命令通过真实 Console/File HumanIO 提问，并创建追加式复核记录，不重新调用模型，也不修改原始任务结果。再次复核必须用 `--supersedes` 指定当前复核 ID。命令和证据边界见[环境配置](SETUP.md)。

## 框架检查与源码变更

**`tests/` 是老师评测题吗？**

不是。三个目录的用途如下：

| 目录 | 内容 | 说明 |
| --- | --- | --- |
| `tests/` | 代码功能、接口、存储、编排及回归测试，也包含题库加载/评测框架本身的检查 | 用于检查系统实现；其中的 FakeLLM 和脚本人类属于测试替身 |
| `eval/tasks/` | 老师发布的原始 Markdown mid-test | 唯一随附题库，正式任务评测的默认题源 |

`tests/` 全绿不能证明老师六目标通过。有意义的回归源码应与所保护的功能一起保留在仓库；运行缓存、临时数据库和测试输出不提交。

**`make test` 与 pytest 有什么区别？**

`make test` / `make eval` 运行真实老师会话；`make unit-test` 或 `python -m pytest -q` 运行框架回归。确定性演示和脚本人类替身是框架检查，不是模型实测成绩或实际质量授权。

**只想检查一个集成边界**

```powershell
python -m pytest tests/test_tool_contract.py -q
python -m pytest tests/test_channel_contract.py -q
python -m pytest tests/test_contracts.py -q
```

这些是建议命令，不表示当前开发版本已经通过。共享模型/接口变更需要与消费模块协调，并更新相关测试和[接口文档](INTERFACES.md)。

## Git 与证据保存

**提交前需要检查什么？**

先 fetch 远端 `main`，与开发分支比较，检查准确 diff 和暂存路径。P3 使用 `dev-P3`。暂存或提交之前先展示简洁英文 commit 和准确文件范围，确认后再操作；合并和推送单独确定。不要包含 `.env`、本地规划、运行产物或私有证据；有意义的回归源码与它所保护的代码一起维护。

**Git 通过本地代理连接失败**

检查相关仓库和环境配置。如果本地代理不可用，可在审阅后采用单次命令覆盖；避免为了临时问题修改所有项目共享的全局 Git 配置。

**可以删除 `runs/` 吗？**

它包含本地数据库、连续工作区、对话、人类决定和交付产物。清理前保留相关 `runs/test/<id>/` 完整目录，单份报告不能替代原始证据。不要删除正在运行的会话，或交付证据的唯一副本。[交付清单](DELIVERY.md)说明哪些材料需要与代码仓库分开保存。
